# งานโค้ดของ Naruephon (เติ้ล) — งาน 32 / 60

## เปิดดู

```bash
npm run dev
```

เปิด `/business/demo` ไม่ต้องมี LINE token หรือฐานข้อมูล เพราะใช้ข้อมูลสมมติล้วน.
หน้านี้เป็นข้อเสนอ/ตัวอย่างรายงาน ไม่มีข้อมูลร้านหรือผลผู้ใช้จริง และไม่ใช่หน้าร้านค้า production.

## สิ่งที่ทำใน branch Tle

- `lib/campaigns/demo.ts`: ข้อเสนอร้านหมูกระทะสมมติ ราคา 129 บาท ผู้จ่ายค่าบริการ เงื่อนไข และขอบเขตรายงาน
- `lib/campaigns/report.ts`: สูตรรายได้จากจำนวนใช้สิทธิ์ที่ยืนยันสำเร็จ แยกดู/รับ/ใช้ และต้นทุนที่ยังไม่ทราบ
- `lib/campaigns/money.ts`: รับต้นทุนเป็นบาททศนิยมไม่เกินสองตำแหน่ง เก็บคำนวณเงินเป็นจำนวนเต็มสตางค์
- `app/business/demo/`: หน้าอธิบายธุรกิจ ข้อเสนอ เงื่อนไข รายงานรวม และเครื่องคำนวณสมมติ
- เทสต์รายได้ 20 ครั้ง × 5 บาท = 100 บาท, ไม่คิดเงินจากการดู/รับ, ไม่มีผู้รับ, ต้นทุนไม่ทราบ/ศูนย์/ขาดทุน, จำนวนผิด และความแม่นยำสตางค์

## สัญญาส่งต่อให้พอและโฟรวิว

`calculateCampaignReport` รับข้อมูลรวมเท่านั้น:

```ts
{
  views: 60,                    // จำนวนครั้งที่ดู ไม่ใช่ unique users
  claimed: 30,                  // จำนวนสิทธิ์ที่ออกสำเร็จ
  redeemed: 20,                 // ร้านยืนยันใช้สำเร็จแล้ว นับครั้งเดียวต่อสิทธิ์
  feePerRedemptionSatang: 500,  // 5 บาท ตามข้อตกลงร้าน
  // knownCostSatang: 2500,     // optional: ต้นทุนรวมที่ทีมระบุเอง
}
```

Backend ต้องนับตาม campaign และช่วงวันที่เดียวกันจากข้อมูลที่ตรวจแล้ว; บังคับสิทธิ์ร้าน/แคมเปญที่เซิร์ฟเวอร์.
ห้ามคืนชื่อ user ID แชต หรือประวัติรายจ่ายให้รายงานร้าน. โมดูลนี้ไม่รับรายการส่วนตัวและไม่ query ฐานข้อมูล.
ตัวเลข demo ไม่ควรถูกนำไปอ้างเป็น conversion จริงหรือผลวิจัย.

ก่อนเปิดใช้คูปองจริง ต้องให้ Backend ทำ/ทดสอบ:

1. เจ้าของสิทธิ์ผูกกับตัวตนที่ยืนยันแล้ว ไม่เชื่อ userId จากหน้าจอ
2. ออกโค้ดที่คาดเดาไม่ได้และเก็บถาวร พร้อม campaign, เวลาเริ่ม/หมดอายุ, quota และสถานะ
3. ร้านยืนยันแบบ transaction/atomic update: รับได้เฉพาะ issued → redeemed; คนยืนยันมีสิทธิ์ร้านนั้น
4. ยืนยันโค้ดเดิมซ้ำ/พร้อมกันสองคำขอ เพิ่มยอดใช้และค่าบริการครั้งเดียว
5. หมดอายุ/ถูกยกเลิก/คนละร้านใช้ไม่ได้ ทดสอบขอบเขตเวลาตาม Asia/Bangkok
6. แยกยอดรับกับยอดใช้ และรวมเฉพาะ event สำเร็จในช่วงรายงาน; ปฏิเสธ event ซ้ำ
7. Frontend ใช้งบซื้อเพิ่มจากแผนล่าสุดที่เซิร์ฟเวอร์คำนวณ ก่อนเสนอราคาโปร

ราคา 129 บาทและค่าบริการ 5 บาทเป็นสมมติฐานจากเดโม ไม่ใช่ราคาผู้ให้บริการหรือข้อตกลงร้านจริง.
วันใช้ ระยะเวลา สาขา จำนวนสิทธิ์ และราคา ต้องได้รับการยืนยันก่อนเปลี่ยนเป็นแคมเปญจริง.

## วิธีตรวจเดโม

- ค่าเริ่มต้น ดู 60 รับ 30 ใช้ 20 → รายได้ 100 บาท อัตราใช้ 66.7% ค้างใช้ 10 สิทธิ์
- ยังไม่กรอกต้นทุน → แสดงว่ายังสรุปรายได้หักต้นทุนไม่ได้
- ใส่ต้นทุน 125 บาท → รายได้หักต้นทุนที่กรอก -25 บาท (ไม่เรียกว่าเป็นกำไรสุทธิ)
- ใส่ใช้มากกว่ารับ → ข้อความให้แก้ ไม่มีผลคำนวณเก่าค้างให้เข้าใจผิด
- ใส่ต้นทุนทศนิยมสามตำแหน่ง → ขอให้แก้ ไม่ปัดเศษเงินเงียบ ๆ
- เปลี่ยนตัวเลขแล้วกดคำนวณ: ไม่มี network request ที่ส่งข้อมูลฟอร์ม ไม่มีการบันทึกธุรกรรม

## สถานะตามเกณฑ์บอร์ด

- งาน 32: มีสูตร/ข้อเสนอและตัวอย่างรายงานแล้ว ผลผู้ใช้จริงและต้นทุนจริงยังต้องรวบรวม
- งาน 60: มีข้อเสนอราคา เงื่อนไข และรายงานเดโมแล้ว การออก/ยืนยันโค้ดและ expiry จริงยังรอ Backend
- ยังไม่ถือว่าสองงานเสร็จทั้งหมด และยังไม่ได้รับการตรวจรับจากมินตราหรือร้านค้า
- ไม่มี commit/push/deploy ในรอบนี้


## เชื่อม LINE MINI App บน Tle

- หน้า `/` เป็นหน้าแนะนำสาธารณะ ส่วน `/miniapp` เริ่ม LIFF และตรวจ ID token ที่ `/api/line/verify` ก่อนแสดงหน้าโปร
- `/business/demo` เป็นข้อเสนอและรายงานธุรกิจสมมติแบบสาธารณะ ไม่ใช่หน้ารายงานของร้านจริงหรือพื้นที่ admin
- ใช้ LIFF ID `2012545254-6025ZG1r` และ MINI App Channel ID `2012545254` จาก environment
- คัดลอก `.env.example` ไป `.env.local` แล้วเติม secret/token ฝั่ง server ตาม README ก่อนทดสอบ LINE จริง
- ใน Console เลือก Developing และกำหนด Endpoint URL เป็น `https://<dev-host>/miniapp` เปิดจาก MINI App URL/QR ที่ Console ให้
- ไม่มี mock login หรือปุ่มข้ามการยืนยันตัวตนในหน้าแอปจริง
- ตัวตนที่ตรวจนี้ยังไม่เป็น session สำหรับ API อื่น ทุก API ข้อมูลส่วนตัวในอนาคตต้องตรวจ token และเจ้าของข้อมูลอีกครั้ง
- ยังไม่ deploy และยังไม่ทดสอบบัญชี LINE จริง; หน้าโปรมีเพียงข้อเสนอสมมติ ไม่มีสิทธิ์ที่ออกใช้จริง
- OA มีข้อความต้อนรับ/ช่วยเหลือพร้อมปุ่มเข้า MINI App แล้ว ใช้ Access Token ฝั่ง server และเทสต์ mock เท่านั้น ดู `docs/LINE-OA-DEVELOPING.md`
- หน้าแนะนำมี scroll showcase และ interaction ครบตามขอบเขตใน `docs/DESIGN-REFERENCES.md`; ฟีเจอร์การเงินจริงยังไม่เชื่อมฐานข้อมูล
