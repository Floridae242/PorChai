# LINE OA cards + LIFF entry

Implemented on `Tle`. Production origin supplied by the team: `https://porchai.vercel.app`.
The UI changes in this working tree require a new deployment before they appear on that site.

## What changes

- `/miniapp`: branded, responsive welcome with four swipeable feature cards; all eight supplied mascot animations; static PNG alternatives for reduced motion; opt-in MP4 previews.
- LINE follow events and exact help commands (`เมนู`, `เริ่มต้น`, `วิธีใช้`, `ทดสอบ`, `สวัสดี`): four-card Flex carousel.
- Recorded expenses: Flex receipt using the saved entry ID, actual summary/budget and Thai date. Edit/delete opens `/app/record/:id`; confirmation and ownership checks stay in the app/backend.
- Over-budget confirmation, before-spending advice and plan confirmations: Flex cards preserving the existing postback actions and idempotency rules.
- No automatic points award, fake financial balances or duplicated welcome messages. Numbers in LIFF feature illustrations are labelled examples. Income/OCR/points are not added by this change.

## URLs and environment

Keep the existing MINI App channel and LIFF ID. Developing endpoint should be
`https://porchai.vercel.app/app`; Messaging webhook should be
`https://porchai.vercel.app/api/line/webhook`.

OA buttons use native MINI App/LIFF permanent links relative to the `/app` endpoint: for example,
`https://miniapp.line.me/2012545254-6025ZG1r/record/new` opens `/app/record/new`.
LINE's SDK handles the `liff.state` redirect. External-browser login returns directly to a validated
path under `/app`. No tokens are passed in card URLs. Server APIs still verify every private request.
`/miniapp` remains a branded introduction and compatibility entry; `/app` is the actual MINI App.

Flex mascot images use public HTTPS PNGs. Set server-only `LINE_ASSET_BASE_URL=https://porchai.vercel.app`,
or enable Vercel system environment variables to use `VERCEL_PROJECT_PRODUCTION_URL` automatically.
If neither is available, the cards retain text and buttons without images. WebP animations remain
inside LIFF because Flex image components use PNG/JPEG. Asset URLs must be reachable by LINE without
a Vercel login or deployment-protection challenge.

Set `NEXT_PUBLIC_LIFF_ID`, `LINE_MINIAPP_CHANNEL_ID`, `LINE_LOGIN_CHANNEL_ID`,
`LINE_CHANNEL_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN`, `SUPABASE_URL`, and
`SUPABASE_SERVICE_ROLE_KEY` in the appropriate Vercel environment. Never upload `.env.local`.
The local Developing configuration uses local Supabase; localhost database URLs cannot be used by Vercel.

## Verification

### Review and export Flex JSON

Open `/dev/line-flex` (locally: `http://localhost:3100/dev/line-flex`) for six sample cards
generated by the actual webhook message builders. Every number is fictional and clearly labelled.
Use **คัดลอก Flex JSON** for the `contents` container accepted by LINE Flex Simulator, or
**ดาวน์โหลด payload** for `{ "messages": [...] }` usable with LINE's validation API.
There is no reply token, channel access token or real account data in the export.

Preview buttons only show an action description; they never fetch a financial API. Sample
postbacks deliberately have an empty draft key, which the webhook rejects, so sending an example
from the Simulator cannot confirm a real expense. The production webhook always uses real event keys.

```sh
npm test
npm run test:db
npm run lint
npm run typecheck
npm run build
node scripts/check-line.mjs --url https://porchai.vercel.app --live
```

The live check sends only empty webhook events and checks the bot token; it does not message users.
LINE's `/v2/bot/message/validate/reply` validates Flex JSON without sending a message. Validate both
carousel and receipt/action bubbles when changing layouts.

After deploying, use a permitted Tester account while the channel is Developing:

1. Send `เมนู` to the OA; swipe all four cards and open a card's button.
2. Complete LINE authorization; the selected LIFF route should open after server verification.
3. Set a money cycle, then send `ข้าว 45`. Check the receipt, actual balance and edit button.
4. Edit or cancel the entry in LIFF and confirm the summary updates. Do not expect old LINE messages to mutate.
5. Send an amount above today's budget; confirm the original pay/try postback buttons still work and tapping twice records only once.
6. Check mobile, tablet, keyboard focus and reduced motion. Videos must play only on request.
