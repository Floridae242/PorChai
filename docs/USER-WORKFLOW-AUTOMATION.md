# PorChai · Automation สำหรับนำเสนอ Workflow ผู้ใช้

ใช้ Playwright ที่มีในโปรเจกต์เพื่อกดหน้าจอและบันทึกวิดีโอ ใช้ Vitest สำหรับแชตผ่าน signed webhook และฐานข้อมูล Supabase บนเครื่อง ไม่ต้องติดตั้ง Python/Robot Framework เพิ่ม

## รันเดโม

```bash
# ครั้งแรก ถ้ายังไม่มี Chromium
npx playwright install chromium

# เปิด Docker/Supabase บนเครื่อง และตั้ง .env.test.local ตาม README ก่อน
# รันครบ: ตรวจแชต → สร้างบทสนทนา → เปิดเบราว์เซอร์เล่นแชต → ใช้ MINI App
npm run demo:workflow

# MINI App อย่างเดียว ไม่ต้องมีฐานข้อมูล/LINE token
npm run demo:miniapp

# รันเบื้องหลังสำหรับตรวจอัตโนมัติ
npm run demo:workflow:ci
npm run demo:miniapp:ci

# เปิดรายงานพร้อมภาพ วิดีโอ และ trace
npm run demo:report
```

โหมดเปิดเบราว์เซอร์หยุดให้ผู้ชมอ่านแต่ละ checkpoint 1.2 วินาที ส่วนคำสั่ง :ci ไม่หยุดรอ ปรับได้ตั้งแต่ 0–5 วินาที:

```bash
DEMO_PAUSE_MS=2500 npm run demo:workflow
DEMO_PAUSE_MS=0 npm run demo:workflow:ci
```

เดโมแต่ละ test เริ่ม fixture ใหม่ ทดสอบซ้ำได้ ใช้เซิร์ฟเวอร์เฉพาะ `http://127.0.0.1:3117` และ `.next-presentation` แยกจาก dev server ปกติ ถ้าพอร์ตถูกใช้ suite จะหยุด ไม่ใช้เซิร์ฟเวอร์อื่นแทน ไม่ต้องเปลี่ยน `.env.local` เป็น mock

## ขอบเขตที่ต้องบอกผู้ชม

- C01 ที่เห็นในเบราว์เซอร์คือ **replay จาก response JSON ที่ signed webhook และ local DB ตรวจผ่านแล้ว** หน้าตาเป็น semantic preview ไม่ใช่ LINE Flex renderer และไม่ได้ส่งข้อความจากบัญชี LINE จริง ปุ่มใน replay ไม่เชื่อม production
- MINI App เปิดหน้า `/app` ของโปรเจกต์จริงในโหมด mock ไม่ผ่าน LIFF login จริง และใช้ข้อมูลคนละ session กับแชต ไม่ใช่การยืนยันว่าแต้ม/ยอด sync ข้ามช่องทางใน production
- ฐานข้อมูลในส่วนแชตเป็น local Supabase จริง มี guard ปฏิเสธ URL cloud สร้างผู้ใช้ UUID ของตัวเองและล้างเฉพาะข้อมูล test นั้นหลังจบ ไม่มี `db reset`
- LINE delivery/identity และ LLM ถูกจำลอง จึงนำเสนอ rule/calculation/fallback ได้ แต่ไม่ใช่หลักฐานว่าความเข้าใจภาษาของ LLM หรือ Google Search จริงผ่านแล้ว
- การแจ้งเตือนตรวจเฉพาะคำสั่ง/ผลตั้งค่า ไม่รอ scheduler หรือส่งข้อความจริง ไม่รวม OCR จากภาพจริง การรับของรางวัลจริง หรือการจ่ายเงินจริง
- เบราว์เซอร์อนุญาต network เฉพาะ localhost; รูปที่เป็น URL ภายนอกอาจไม่แสดง ห้ามเปลี่ยน target เป็น production เพื่อให้ “ดูเหมือนจริง”

## ผลลัพธ์และการแก้ปัญหา

- `artifacts/presentation/report/index.html`: รายงานเปิดดูแต่ละขั้น/ภาพแนบได้
- `artifacts/presentation/results/`: วิดีโอ `.webm`, trace `.zip`, ภาพเมื่อ fail
- `artifacts/presentation/results.json`: สถานะและเวลาสำหรับเครื่องมืออื่น
- `artifacts/presentation/chat-transcript.json`: บทสนทนาที่ผ่าน backend run ล่าสุด; runner ลบไฟล์เก่าก่อนทดสอบและหยุดทันทีเมื่อ backend fail
- artifacts ไม่เข้า Git เพราะอาจมีข้อมูลจากการทดสอบ ห้ามนำ credentials หรือข้อมูลลูกค้าจริงมาใช้เป็น fixture

หากฐานข้อมูลเข้าไม่ได้ ตรวจ Docker/Supabase และ `.env.test.local` ตาม README หากไม่มี Chromium รันคำสั่งติดตั้งด้านบน หาก test ล้ม ให้ดูขั้นสีแดงใน HTML report อย่าเปลี่ยน assertion ให้ผ่านโดยไม่ได้ตรวจพฤติกรรมจริง
