จดหลายรายจ่ายได้ครั้งละ 2–5 รายการในข้อความเดียว คั่นด้วยช่องว่าง เครื่องหมายจุลภาค หรือขึ้นบรรทัดใหม่ ระบุชื่อกับยอดของแต่ละรายการ ไม่ใส่ยอดรวมปน ไม่รวมรายรับ รายการอนาคต หรือจำนวนสินค้าเข้ากับยอดเงิน ระบบไม่บันทึกจนกดยืนยัน กดซ้ำไม่เพิ่มรายการซ้ำ และได้รับแต้มรายวันเพียงครั้งเดียว

ตั้งค่าในแชตด้วยจำนวนบาท ระบบแปลงเป็นสตางค์และตรวจด้วย validator เดิม จำนวนกำกวมให้ถามเพิ่ม การตั้งรอบไม่สมมติแหล่งเงินหรือความถี่ หากข้ามค่าใช้จ่ายจำเป็นจะยังไม่สรุปว่าเงินพอแน่นอน เงินที่แจ้งก่อนมีรอบยังไม่บันทึก และยอดตั้งต้นไม่สร้างรายรับซ้ำ

ร่างยืนยันมี nonce ฝั่งเซิร์ฟเวอร์และอายุ 30 นาที เฉพาะเจ้าของบัญชีค้นร่างได้ ไม่รับยอด/ID จากปุ่มโดยตรง ยืนยันหรือยกเลิกใช้ database lease ป้องกันการทำซ้ำข้าม webhook และตรวจ budget basis/ข้อมูลเดิมก่อนแก้ การแก้รายจ่ายที่มาจากแผนยังอยู่ใต้กฎเดิม ต้องยกเลิกการจ่ายที่แผน

AI ช่วยจำแนกคำขอดูข้อมูลที่กฎไม่รู้จัก โดยเลือกได้เฉพาะ read tools และคำค้นต้องอยู่ในข้อความผู้ใช้จริง ไม่มีสิทธิ์สร้าง mutation, account ID หรือ record ID จากผลโมเดล คำสั่งตรงทำงานได้แม้ AI ไม่พร้อม

ข้อจำกัด: รายการเลือกแสดงไม่เกิน 10 รายการต่อหน้า ใช้ ดูแผน หน้า 2 และ จ่ายบิล 1 หน้า 2 เพื่อเลือกงวดถัดไป ค้นแสดงรายละเอียดล่าสุด 5 รายการพร้อมยอดรวมทั้งหมด ไม่ใช่การค้นเชิง semantic ค้นเว็บยังใช้หน้าที่แสดง citation และ widget ของผู้ให้บริการ ส่วนคูปองจริงที่ backend ยังไม่รองรับไม่ได้ถูกทำให้สำเร็จเทียม · ลบข้อมูลบัญชีทำได้ในแอป (ตั้งค่า › ลบข้อมูลของฉัน, `DELETE /api/me`) แชตไม่ลบให้: พิมพ์ «ลบข้อมูลได้ไหม» จะได้ปุ่มไปหน้านั้น การส่ง digest จริงต้องตั้ง migration/environment/scheduler ตาม REPORTS-NOTIFY-SEARCH.md

ทดสอบด้วย `npm test`, `npm run test:db` (ฐาน local เท่านั้น), `npm run lint`, `npm run typecheck`, `npm run build` เทสต์ใช้ LINE/Gemini จำลองและไม่ส่งข้อความจริง


## ผ่อนสินค้าผ่านแชต

ตัวอย่าง `ผ่อน โทรศัพท์ ยอดรวม 12000 บาท 12 งวด เริ่ม 2026-12-01` หรือ `ผ่อน โทรศัพท์ งวดละ 1000 บาท 12 งวด เริ่ม 2026-12-01` แล้วตรวจ Flex Card และยืนยันก่อนสร้างบิล ระบุยอดคงเหลือที่ต้องจ่ายจริงรวมต้นทุนทั้งหมดเอง ไม่ใช่ราคาป้ายสินค้า ไม่รวมเงินดาวน์ที่จ่ายแล้ว ไม่เดา APR/ค่าธรรมเนียม และไม่ได้ติดต่อหรือชำระให้ร้านค้า

เติม `ไหวไหม` ท้ายคำสั่งเดียวกันเพื่อลองคำนวณโดยไม่สร้างบิล ผลอิงยอดและวันรับเงินรอบปัจจุบัน ไม่ทำนายรายรับหรือรับรองว่าจะผ่อนไหวทุกเดือน ถ้าค่าใช้จ่ายจำเป็นยังไม่ตั้ง ระบบจะระบุว่าประเมินส่วนนี้ไม่ได้

รองรับรายเดือน 1–60 งวด ยอดรวมมากกว่า 0 และไม่เกิน 100,000 บาท แต่ละงวดอย่างน้อยหนึ่งสตางค์ เศษสตางค์กระจายให้ยอดรวมตรงเป๊ะ ไม่เกินหนึ่งสตางค์ระหว่างงวด วันที่ 31 จะใช้วันสุดท้ายในเดือนสั้นและกลับมาวันที่ 31 ในเดือนที่มี วันที่เริ่มต้องไม่ย้อนหลัง งวดครบในรอบปัจจุบันจึงกันเงิน บิล reserved ที่ยังไม่จ่ายย้ายไปรอบเงินใหม่ด้วยกลไกเดิม

สร้างทุกงวดใน RPC transaction เดียว ใช้ key ป้องกันการกดซ้ำ/เครือข่ายขาดหลัง commit ตรวจเจ้าของบัญชี รอบเงิน และ budget basis ของผลที่แสดงก่อนยืนยัน จ่ายจริงทีละบิลด้วย `จ่ายบิล 1` และยกเลิกการจ่ายด้วย `ยกเลิกการจ่ายบิล 1` ตามสถานะเดิม การเลื่อนหรือยกเลิกในแชตเปลี่ยนเฉพาะแผนในแอป ไม่ได้แก้สัญญาหนี้กับผู้ขาย

ต้อง apply `20261116020000_installments.sql` ก่อนใช้งานบน hosting รอบพัฒนานี้ apply เฉพาะฐาน local และไม่ deploy ไม่มีการล้างข้อมูล

เทสต์ failure injection สำหรับ atomic rollback และสิทธิ์ RPC: `docker exec -i supabase_db_PorChai psql -U postgres -d postgres -v ON_ERROR_STOP=1 < supabase/tests/installments-atomic.sql` ใช้เฉพาะฐาน local สคริปต์ rollback constraint และ fixtures ทั้งหมด
