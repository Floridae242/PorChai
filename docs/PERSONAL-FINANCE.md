# แต้มอัตโนมัติ หมวดส่วนตัว และวิเคราะห์รายการที่จด

## แต้ม

บันทึกรายรับหรือรายจ่ายใหม่ของวันที่ปัจจุบันตามเวลาไทยสำเร็จ ได้ 1 แต้มอัตโนมัติผ่าน database trigger ใน transaction เดียวกับรายการนั้น รวมจ่ายบิล/แผน ยืนยัน OCR และรายการจาก LINE การจดหลายรายการพร้อมกัน การส่ง webhook ซ้ำ และกดรับแต้มเองใช้เพดานเดียวกันวันละ 1 แต้ม

รายการร่าง การลองก่อนจ่าย รายการย้อนหลัง และแก้รายการเดิมไม่ได้แต้มเพิ่ม ยกเลิกรายการไม่หักแต้มกิจกรรมที่เคยได้ และไม่ทำให้รับซ้ำได้ วันไม่มีรายจ่ายยังใช้การเช็กแผนและกดรับแบบเดิมได้ หากบันทึกล้มเหลว แต้มต้องไม่เพิ่ม หากเพิ่มแต้มล้มเหลว transaction ของรายการใหม่ rollback ด้วย ไม่มีการแจกย้อนหลังให้ประวัติเดิมตอนติดตั้ง migration

## หมวดและงบรายเดือน

`/app/settings/categories` บันทึกชื่อหมวด งบรายเดือน และหมวดย่อยได้จริง พร้อมหน้าตรวจและยืนยัน `null` คือยังไม่ตั้งงบ ส่วน 0 คืองบศูนย์บาท หมวดมี 5 กลุ่มหลักเดิมและสร้างหมวดย่อยใต้ 4 กลุ่มรายจ่ายได้ รวมสูงสุด 100 หมวดต่อบัญชี ชื่อยาว 1–30 ตัวอักษร งบ 0–100,000 บาท กลุ่มของหมวดเดิมเปลี่ยนไม่ได้เพื่อรักษาการจัดกลุ่มประวัติ แต่ชื่อและงบแก้ได้ด้วย version ป้องกันข้อมูลเก่าทับข้อมูลใหม่

บันทึกรายจ่ายเลือกหมวดส่วนตัวได้ `categoryId` ผูกกับเจ้าของบัญชีและกลุ่มแม่ด้วย foreign key/trigger เปลี่ยนชื่อหมวดไม่ทำให้รายการเดิมหลุดหมวด แก้จำนวนเงินอย่างเดียวไม่ล้างหมวดส่วนตัว งบเหล่านี้ใช้ติดตาม ไม่ได้เพิ่มเงินที่ใช้ได้หรือกันเงินซ้ำในสูตรแผนเงิน

ยอดหมวดหลักรวมหมวดย่อยอยู่แล้ว เช่น ชานม 50 บาทอยู่ใต้ อาหาร จะแสดง 50 บาทในทั้งสองระดับ แต่ยอดรวมรายจ่ายยังเป็น 50 บาท ห้ามนำสองระดับมาบวกซ้ำ หมวดบิลใช้กับการจ่ายบิล/แผนเดิม

## สรุปและวิเคราะห์

หน้าสรุปเดิมเปิดภาพรวมเดือนนี้ได้ทันที และมีทางไป `/app/reports` กับ `/app/insights` ซึ่งแสดงข้อมูล 30 วันล่าสุด จำนวนรายการ จำนวนวันที่มีการจด ค่าเฉลี่ยต่อรายการ ยอด 7 วันล่าสุดเทียบ 7 วันก่อนหน้า วันในสัปดาห์ รายการข้อความเดิมที่พบอย่างน้อย 3 วัน และงบรายหมวดของเดือนปัจจุบัน ยอดจากรายการจ่ายแผนนับเพียงครั้งเดียว รายการยกเลิกไม่รวม ทุก query จำกัดบัญชีที่ยืนยันตัวตน

ข้อสังเกตใช้กฎจากรายการที่จด ไม่สรุปว่าวันที่ไม่มีรายการคือไม่จ่าย และไม่อ้างว่าแนวโน้มที่ลดลงแปลว่านิสัยดีขึ้นแน่นอน งบแนะนำตั้งต้นใช้ยอดที่จดเดือนนี้ ไม่ใช่ประมาณการเต็มเดือนหรือการรับรองว่าจ่ายไหว ผู้ใช้แก้และยืนยันก่อนนำไปใช้

AI ช่วยอธิบายเมื่อผู้ใช้กดหรือพิมพ์ `AI วิเคราะห์` เท่านั้น ใช้เฉพาะ observations/suggestions ของบัญชี ไม่มีสิทธิ์เปลี่ยนงบหรือบันทึกเอง ข้อมูลน้อยกว่า 3 รายการ/3 วันที่จด หรือคำตอบที่แต่งตัวเลข/อ้างว่าแก้ข้อมูลแล้ว จะใช้ข้อสังเกตจากโค้ดแทน ไม่เรียกค้นเว็บ

## คำสั่ง LINE

- `ดูภาพรวม` / `สรุป` / `ดูรายงานวันนี้`
- `ดูหมวด` / `วิเคราะห์` / `AI วิเคราะห์`
- `เพิ่มหมวด ชานม กลุ่ม อาหาร งบ 500 บาท` แล้ว `ยืนยัน`
- `ตั้งงบ ชานม 800 บาท` แล้ว `ยืนยัน`
- `จด ชานม 50 หมวด ชานม` แล้ว `ยืนยัน`
- พิมพ์รายจ่ายแยกบรรทัด เช่น `ข้าว 45` และ `รถเมล์ 20` → ตรวจรายการและกดจดทั้งหมด

ข้อความหลายบรรทัดรองรับรายจ่ายชัดเจนไม่เกิน 5 รายการ ถ้าปนรายรับ จำนวนกำกวม หรือคำถาม จะถามเพิ่ม ไม่เหมารวมเป็นรายจ่าย ถ้ามีรายการแรกสำเร็จแล้วรายการถัดไปขัดข้อง การ retry ใช้ key เดิมของแต่ละรายการ ไม่สร้างรายจ่ายซ้ำ

## ก่อนใช้งานบน hosting

ต้อง apply migration `20261116040000_personal_categories_auto_points.sql` หลัง migrations ก่อนหน้า รอบนี้ใช้เฉพาะฐาน local ไม่ deploy ไม่ส่ง LINE push และไม่เรียกผู้ให้บริการ AI จริงระหว่างทดสอบ

ทดสอบด้วย `npm test`, `npm run test:db` (guard localhost เท่านั้น), `npm run lint`, `npm run typecheck`, `npm run build` และ browser mock ที่ความกว้าง 390px
