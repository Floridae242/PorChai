# PorChai — สถานการณ์สาธิตและทดสอบผ่าน LINE

จัดทำ 16 พฤศจิกายน 2569 · อ้างอิงโค้ด `e205d46` และคำสั่งใน [CHAT-COMMANDS.md](CHAT-COMMANDS.md)

เอกสารสำหรับผู้สาธิต: เลือกใช้สคริปต์สั้นด้านล่างเมื่อนำเสนอ และใช้สถานการณ์เพิ่มเติมเมื่อลูกค้าต้องการลองเอง รายการคำสั่งและคำตอบตามบริบทอยู่ใน [LINE-CHAT-KEYWORDS.csv](LINE-CHAT-KEYWORDS.csv) เปิดด้วย Excel/Google Sheets ได้

ข้อความในช่อง `พิมพ์` คัดลอกไปส่งได้ ส่วนข้อความในวงเล็บ เช่น **[กด จดทั้งหมด]** เป็นการกดปุ่มบนการ์ด ไม่ใช่ข้อความที่ให้พิมพ์

ส่งทีละข้อความและรอผลก่อนทำขั้นถัดไป ยกเว้นตัวอย่างหลายรายจ่ายที่ระบุให้ส่งในข้อความเดียว ตาราง keywords รวมคำสั่งหลัก รูปแบบคำสั่ง และคำตอบที่ต้องใช้ตามบริบท ไม่ใช่การรับรองว่าจะตีความทุกประโยคภาษาธรรมชาติได้เหมือนกัน

## เตรียมก่อนเริ่ม สำหรับทีม

- ใช้ LINE บัญชีทดสอบที่เพิ่มเพื่อน OA แล้ว และตรวจว่าเครื่องที่สาธิตใช้บัญชีเดียวกันกับ MINI App
- ใช้บัญชีทดสอบแยกจากข้อมูลส่วนตัว เพราะการจดและกดยืนยันในระบบจริงเปลี่ยนข้อมูลจริง
- ตรวจว่าเวอร์ชันที่ให้ลูกค้าทดลองมีโค้ดและฐานข้อมูลที่รองรับฟีเจอร์แล้ว การ merge โค้ดไม่ได้ยืนยันผลบน LINE จริง
- วันที่ตัวอย่างใช้ `2026-11-30` เป็นวันรับเงินและ `2026-11-20` เป็นวันครบกำหนดบิล/งวดแรก ต้องเปลี่ยนเป็นวันที่จริงก่อนสาธิตเมื่อวันที่เหล่านี้ผ่านไป โดยวันรับเงินต้องอยู่หลังวันนี้
- เริ่มด้วย S01 สำหรับบัญชีใหม่ หากมีรอบเงินอยู่แล้ว ให้ตรวจข้อมูลเดิมก่อน ไม่เริ่มรอบใหม่ทับเพื่อรีเซ็ตเดโม
- จดวันแรกได้ 1 แต้มอัตโนมัติเท่านั้น ถ้าเคยรับแต้มวันนี้แล้วจะไม่เพิ่มอีก ยอดเดิมและแค็ตตาล็อกรางวัลของแต่ละบัญชีอาจต่างกัน
- ทดสอบส่งการแจ้งเตือนตามเวลาล่วงหน้าแยกต่างหาก การเปิดการเตือนไม่ทำให้มีข้อความส่งมาทันที

## สคริปต์นำเสนอหลัก 10–15 นาที

คำเกริ่นที่ใช้ได้: “พอใช้ช่วยให้จดและดูแผนเงินจากแชต LINE ได้ ลองใช้ชีวิตนักศึกษาหนึ่งวัน ตั้งแต่รับเงิน จดอาหาร แก้รายการ ไปจนถึงเช็กว่าซื้อของเพิ่มไหวหรือไม่”

| ลำดับ | เล่าให้ลูกค้าฟัง | พิมพ์ / การกระทำ | สิ่งที่ควรเห็น |

| 1 | เรียนรู้ได้โดยไม่ต้องจำเมนู | `ขอวิธีใช้ทั้งหมด` | Flex Carousel แนะนำฟีเจอร์ เลื่อนดูได้ ยังไม่จดรายการตัวอย่าง |
| 2 | ตั้งแผนเงินครั้งแรก | ทำ S01 ด้านล่าง หากยังไม่มีรอบเงิน | ถามข้อมูลทีละข้อ แล้วให้ตรวจและยืนยัน |
| 3 | รับเงินเพิ่มระหว่างรอบได้ในแชต | `ได้รับเงิน 1000 บาท` | บันทึกรายรับ 1,000 บาท ยอดเงินจริงอัปเดต |

| 6 | จดผิดก็แก้รายการเดิม | `แก้ยอดล่าสุด 25 บาท` → `ยืนยัน` | ตรวจว่ารายการล่าสุดคือรายการใดก่อนยืนยัน จำนวนนั้นเปลี่ยนเป็น 25 บาท ไม่เพิ่มรายการ |
| 7 | ขอภาพรวมได้ทันที | `ดูรายงานวันนี้` | สรุปรายรับ รายจ่าย และผลต่างจากรายการที่จด |
| 8 | ให้ช่วยคิดก่อนจ่าย | `ชาบู 199 บาท ไหวไหม` | ผลประเมินจากแผนปัจจุบัน ยังไม่บันทึกรายจ่ายและไม่เปลี่ยนยอดเงินจริง |

## สถานการณ์หลักสำหรับให้ลูกค้าทดลอง

### S01 — เริ่มใช้โดยตั้งรอบเงินในแชต

**เงื่อนไข:** บัญชีใหม่ที่ยังไม่มีรอบเงิน ใช้ยอดสมมติสำหรับบัญชีทดสอบเท่านั้น ส่งทีละข้อความ รอคำถามก่อนตอบข้อถัดไป

| ขั้น | พิมพ์ | ความหมาย / ผลที่ควรเห็น |
|---|---|---|
| 1 | `เริ่มรอบเงิน` | ถามแหล่งเงิน |
| 2 | `เงินจากบ้าน` | ถามความถี่ |
| 3 | `รายเดือน` | ถามยอดเงินจริงตอนนี้ |
| 4 | `3000` | ตั้งยอดเงินที่มีอยู่จริง 3,000 บาท ยังไม่สร้างรายรับ 3,000 ซ้ำ |
| 5 | `2026-11-30` | วันรับเงินรอบถัดไป ต้องเปลี่ยนเป็นวันในอนาคตก่อนใช้ |
| 6 | `300` | กันเงินออม 300 บาท |
| 7 | `200` | กันเงินเผื่อฉุกเฉิน 200 บาท |
| 8 | `50` | ค่าอาหารจำเป็นวันละ 50 บาท |
| 9 | `20` | ค่าเดินทางจำเป็นวันละ 20 บาท |
| 10 | `ยืนยัน` | ตรวจการ์ดสรุปก่อน แล้วจึงสร้างรอบเงิน |
| 11 | `วันนี้ใช้ได้เท่าไหร่` | เห็นงบตามยอดและจำนวนวันของรอบนี้ |

แหล่งเงินเลือกได้ `เงินจากบ้าน` / `ทุน` / `งานพิเศษ` / `อื่นๆ`; ความถี่เลือก `รายสัปดาห์` / `รายเดือน` / `ไม่แน่นอน` ได้ หากยังไม่ทราบค่าจำเป็นให้ตอบ `ข้าม` ตอนถามค่าอาหาร ระบบจะระบุว่ายังประเมินส่วนนี้ไม่ได้

### S02 — บันทึกรายรับระหว่างรอบ

พิมพ์ `ได้รับเงิน 1000 บาท` แล้ว `ดูรายงานวันนี้`

**ตรวจ:** รายรับเพิ่ม 1,000 บาท ไม่ใช่รายจ่าย ไม่ต้องเปิดแอป หากพิมพ์ข้อความรายรับเดิมส่งใหม่อีกครั้งจะเป็นคนละรายการจริง จึงไม่ใช้การส่งข้อความซ้ำเพื่อทดสอบกันซ้ำของระบบ

### S03 — รายจ่ายหนึ่งรายการและแต้มอัตโนมัติ

พิมพ์ `ข้าว 50` → `ดูแต้ม` → `กาแฟ 35` → `ดูแต้ม`

**ตรวจ:** มีรายจ่ายสองรายการ ยอด 50 และ 35 บาท ได้แต้มรายวันเพิ่มได้สูงสุด 1 แต้ม แม้จดหลายครั้งในวันเดียว ถ้าเกินงบวันนี้อาจขึ้นการ์ดถามก่อน ให้ตัดสินใจว่าจะยืนยันจ่ายจริงหรือยกเลิกตามการ์ด

### S04 — หลายรายจ่ายพร้อมกัน

ส่งเป็นข้อความเดียว:

```text
ข้าว 45
รถเมล์ 20
น้ำ 15
```

**ตรวจ:** ร่าง 3 รายการ รวม 80 บาท ก่อนกด **จดทั้งหมด** ยังไม่มียอดเพิ่ม เมื่อยืนยันแล้วจดครบ กดปุ่มเดิมซ้ำต้องไม่เพิ่มรายการซ้ำ รองรับรายจ่ายชัดเจน 2–5 รายการต่อข้อความ ไม่รวมรายรับหรือยอดรวมปน

### S05 — แก้ยอดแบบระบุยอดใหม่ทันที

พิมพ์ `ข้าว 50` → `แก้ยอดล่าสุด 40 บาท` → `ยืนยัน` → `ดูรายการ`

**ตรวจ:** รายการข้าวที่เพิ่งจดยังเป็นรายการเดิม หมวดเดิม เปลี่ยน 50 เป็น 40 บาท เงินเพิ่มกลับ 10 บาท ไม่มีรายจ่ายชื่อ “แก้ยอดล่าสุด” และไม่แจกแต้มซ้ำ

### S06 — แก้ยอดด้วยการคุยต่อ

พิมพ์ `แก้รายการล่าสุด` → รอถามยอด → `ใช่ 35 บาท` → ตรวจการ์ด → `ยืนยัน`

**ตรวจ:** ก่อนยืนยันยอดเดิมยังอยู่ หลังยืนยันจึงแก้เป็น 35 บาท คำตอบ `ใช่ 35` ใช้ได้เมื่อระบบมีคำขอแก้ที่ผูกกับรายการแล้วเท่านั้น

### S07 — ยกเลิกคำขอ / ลบรายการที่จดผิด

1. พิมพ์ `แก้ยอดล่าสุด 30` → `ยกเลิก` → `ดูรายการ` — ยอดเดิมต้องอยู่
2. พิมพ์ `ลบรายการล่าสุด` → อ่านชื่อและยอด → `ยืนยัน` — รายการนั้นถูกยกเลิกและไม่รวมในยอดอีก

หากต้องเลือกแถวอื่น ใช้ `แก้รายการ 2 เป็น 40 บาท` หรือ `ลบรายการ 2` โดยดูหมายเลขจากรายการล่าสุดก่อน ทุกครั้งต้องตรวจชื่อในคำยืนยัน

### S08 — ถามก่อนจ่ายโดยไม่จดรายจ่าย

พิมพ์ `ชาบู 199 บาท ไหวไหม` → ดูผล → **[กด ลองยอดอื่น]** → ตอบ `129`

**ตรวจ:** แสดงผลลองจ่ายตามแผนล่าสุด ไม่หักเงินจากการถามหรือเปลี่ยนราคา หากต้องการบันทึกจริงให้ใช้ปุ่ม **ยืนยันจ่ายจริง** หลังจ่ายจริงเท่านั้น ปุ่มที่มีขึ้นกับชนิดการ์ดและวันที่ลอง

### S09 — ถามงบและวันเงินเข้า

ลองทีละคำสั่ง: `วันนี้ใช้ได้เท่าไหร่`, `เหลือเท่าไร`, `วันเงินเข้าเมื่อไร`, `อีกกี่วันเงินเข้า`, `เงินพอถึงวันเงินเข้าไหม`

**ตรวจ:** ตัวเลขมาจากแผนปัจจุบัน ไม่ใช้ตัวเลขในข้อความเก่า และไม่สรุปว่าเงินพอแน่นอนเมื่อข้อมูลจำเป็นยังไม่ครบ

### S10 — เรียกสรุปและค้นประวัติ

ลอง `ดูรายงานวันนี้`, `ดูรายงานเดือนนี้`, `ดูรายงานเดือนที่แล้ว`, `สัปดาห์นี้ใช้ไปเท่าไร`, `ค้นรายจ่าย ข้าว`, `ค้นรายจ่าย กาแฟ วันนี้`

**ตรวจ:** รายงานแยกช่วงเวลา ค้นเฉพาะข้อมูลบัญชีนี้ หากไม่มีรายการควรบอกว่าไม่มีข้อมูล ไม่สร้างตัวเลขใหม่ ผลต่างรายรับ−รายจ่ายไม่จำเป็นต้องเท่ากับยอดเงินคงเหลือ เพราะยอดตั้งต้นไม่ใช่รายรับที่จดใหม่

### S11 — สร้างหมวดและงบให้เข้ากับตัวเอง

พิมพ์ทีละคำสั่ง:

1. `ดูหมวด`
2. `เพิ่มหมวด ชานม กลุ่ม อาหาร งบ 500 บาท` → `ยืนยัน`
3. `จด ชานม 35 หมวด ชานม` → `ยืนยัน`
4. `ตั้งงบ ชานม 400 บาท` → `ยืนยัน`
5. `ดูหมวด`

**ตรวจ:** หมวดย่อยมีงบรายเดือนและรายจ่ายเข้าหมวดถูกต้อง ตั้งงบไม่ทำให้เงินในบัญชีเพิ่ม กลุ่มที่ใช้สร้างหมวดได้คือ `อาหาร`, `เดินทาง`, `ของใช้`, `อื่นๆ` ชื่อหมวดต้องตรงกับชื่อที่สร้าง

### S12 — วิเคราะห์พฤติกรรมและข้อเสนอแนะ

พิมพ์ `วิเคราะห์` → `แนะนำงบ` → `AI วิเคราะห์`

**ตรวจ:** ข้อสังเกตอิงรายการที่จดจริง พร้อมช่วงข้อมูล ข้อเสนอเป็นคำแนะนำ ไม่เปลี่ยนงบเอง หากมีข้อมูลเพียงวันเดียวไม่ใช้แสดงว่าเรียนรู้พฤติกรรมหลายวันได้แล้ว ส่วน AI ต้องมีบริการพร้อมจึงจะมีคำอธิบายเพิ่มเติม

### S13 — เพิ่มบิลและจ่ายบิลจากแชต

พิมพ์ `เพิ่มบิล ค่าอินเทอร์เน็ต 300 บาท วันที่ 2026-11-20` → `ยืนยัน` → `ดูแผน`

ดูหมายเลขของบิลที่เพิ่งเพิ่ม หากเป็นหมายเลข 1 ให้พิมพ์ `จ่ายบิล 1` → `ยืนยัน`

**ตรวจ:** ตอนเพิ่มบิลเป็นแผนกันเงิน ยังไม่ใช่รายจ่าย ตอนยืนยันจ่ายจึงสร้างรายจ่ายจากบิลหนึ่งครั้ง หากจดว่าจ่ายผิด ใช้ `ยกเลิกการจ่ายบิล 1` หลังดูหมายเลขปัจจุบัน แล้วตรวจการ์ดก่อนยืนยัน ไม่แก้รายจ่ายบิลแยกจากแผน

### S14 — แผนซื้อที่ยังไม่จ่าย

พิมพ์ `เพิ่มแผน หนังสือ 250 บาท วันที่ 2026-11-20` → `ยืนยัน` → `ดูแผน`

ใช้หมายเลขแผนที่เห็นแทน 1: `เก็บแผน 1`, `เลื่อนแผน 1`, `ยกเลิกแผน 1` แล้วตรวจและยืนยันทีละคำสั่ง เลือกสาธิตเพียงหนึ่งทางต่อแผน ไม่ส่งทั้งสามคำสั่งติดกัน

**ตรวจ:** สถานะแผน/เงินกันเปลี่ยนตามทางที่เลือก ไม่สร้างรายจ่ายจนยืนยันจ่ายจริง

### S15 — ลองผ่อนก่อนสร้างบิล

พิมพ์ `ผ่อน โทรศัพท์ ยอดรวม 6000 บาท 6 งวด เริ่ม 2026-11-20 ไหวไหม`

**ตรวจ:** ตารางลอง 6 งวด งวดละ 1,000 บาท ยังไม่สร้างบิลหรือจดรายจ่าย ไม่รับรองว่าจะผ่อนไหวทุกเดือน เพราะยังไม่ทราบรายรับ/ค่าใช้จ่ายในอนาคตทั้งหมด

ถ้าจะทดลองสร้างจริงในบัญชีทดสอบ ส่งข้อความเดิมโดยตัด `ไหวไหม` ออก → อ่านตารางและยอดรวม → `ยืนยัน` → `ดูแผน`

รูปแบบอีกแบบ: `ผ่อน โทรศัพท์ งวดละ 1000 บาท 6 งวด เริ่ม 2026-11-20` ยอดต้องเป็นภาระที่ต้องจ่ายจริงรวมต้นทุนแล้ว ระบบไม่คำนวณดอกเบี้ย/เงินดาวน์จากคำบรรยายให้

### S16 — ปรับแผนเงินระหว่างรอบ

เลือกสาธิตทีละเรื่องแล้วตรวจ/ยืนยัน:

| พิมพ์ | ความหมาย |
|---|---|
| `ปรับยอด 3500 บาท` | ตั้งยอดเงินจริงปัจจุบันเป็น 3,500 ไม่ใช่รับเงินเพิ่ม 3,500 |
| `กันเงินเผื่อ 300 บาท` | ตั้งเงินเผื่อรวมเป็น 300 ไม่ใช่เพิ่มอีก 300 |
| `ตั้งค่าอาหาร 60 ค่ารถ 20` | ตั้งค่าจำเป็นต่อวันใหม่ |
| `เปลี่ยนวันรับเงิน 2026-12-01` | เปลี่ยนวันเงินเข้าครั้งถัดไป ไม่ได้บันทึกว่าเงินเข้าแล้ว |

**ตรวจ:** ใช้ `วันนี้ใช้ได้เท่าไหร่` หลังยืนยันเพื่อเห็นผล ไม่ใช้ S16 กลางสคริปต์สั้นหากยังต้องการเปรียบเทียบยอดก่อน/หลังของ S05

### S17 — เปิดสรุปรายวัน รายเดือน และเตือนงบ

พิมพ์แต่ละคำสั่งแล้วตรวจ/ยืนยัน: `เปิดสรุปรายวัน เวลา 20:00`, `เปิดสรุปรายเดือน`, `เปิดเตือนงบ` แล้ว `ดูแจ้งเตือน`

**ตรวจทันที:** ค่าที่เลือกเปิดถูกบันทึก ยังไม่จำเป็นต้องมีข้อความแจ้งเตือนส่งมาในเวลานั้น

**ตรวจภายหลังตามเวลา:** รายวันใช้เวลาที่ตั้ง รายเดือนส่งวันที่ 1 เพื่อสรุปเดือนก่อนหน้า เตือนงบส่งเมื่อเข้าเงื่อนไขเกินงบในช่วงเวลาที่รองรับ ต้องมีระบบส่งตามเวลาของเซิร์ฟเวอร์พร้อมและบัญชีรับข้อความจาก OA ได้

หลังทดลองใช้ `ปิดแจ้งเตือน` → `ยืนยัน` → `ดูแจ้งเตือน` เพื่อปิดการสรุปและเตือนงบที่เปิดไว้

### S18 — เตือนรายการที่อาจลืมจด

พิมพ์ `เปิดเตือนจด` → `ยืนยัน` → `ดูเตือนจด`

**เงื่อนไขสำหรับโชว์การส่งจริง:** มีประวัติที่ระบบตรวจพบเป็นรายการประจำ เปิดการเตือน และยังไม่จดรายการนั้นในวันที่ทดสอบ เมื่อเข้าเงื่อนไขควรได้การ์ดให้จด/แก้ยอด/ข้ามตามปุ่มจริง หากจดไปแล้วหรือปิดการเตือน ไม่ควรส่งรายการนั้น

บัญชีใหม่อาจยังไม่พบรายการประจำ ไม่ควรรับปากว่าจะมีการ์ดเตือนทันที ปิดด้วย `ปิดเตือนจด` → `ยืนยัน` การตั้งค่านี้แยกจาก S17

### S19 — แต้มและแลกรางวัล

พิมพ์ `ดูแต้ม` → `เช็กครบแล้ว` → `เช็กครบแล้ว` → `ดูแต้ม`

**ตรวจ:** ถ้ารับแต้มวันนี้แล้วจะไม่เพิ่มซ้ำ การจดและการกดเช็กใช้สิทธิ์รายวันเดียวกัน

ทดลองแลกเมื่อมีแต้มและรางวัลจริงในแค็ตตาล็อก: `แลกของ` → **[เลือกหมายเลขของรางวัล]** → ตรวจแต้มที่จะใช้ → `ยืนยัน` ถ้าไม่มีรางวัล/แต้มไม่พอควรแจ้งตามจริง ไม่สร้างสิทธิ์เทียม

หากต้องตรวจแต้มสองช่องทาง ใช้ `ตรวจแต้ม` แล้วเทียบกับปุ่มตรวจการเชื่อมต่อในหน้าแต้มของ MINI App สำหรับบัญชีเดียวกัน

### S20 — ใบเสร็จ สลิป และการเลือกยอด

ส่งรูปใบเสร็จตัวอย่างในแชต → ตรวจร้าน/ชื่อรายการ ยอด และวันที่ → เลือกยอด/แก้ถ้าจำเป็น → **[กดบันทึกบนการ์ด]**

**ตรวจ:** การส่งรูปอย่างเดียวยังไม่จดเงิน หากอ่านไม่ได้ต้องให้กรอกเอง กรณีสลิปต้องเลือกให้ถูกว่าเป็นรายจ่าย รับเงิน หรือโอนระหว่างบัญชีตัวเอง ก่อนยืนยันตามตัวเลือกบนการ์ด ใช้ภาพทดสอบที่ไม่มีข้อมูลส่วนตัวของลูกค้า

### S21 — โปรตัวอย่างและค้นเว็บ

1. `ดูคูปอง` หรือ `ดูโฆษณา` — เห็น Carousel ที่ระบุผู้สนับสนุนสมมติ ใช้ซื้อจริงไม่ได้ ไม่ได้แลกสิทธิ์หรือหักแต้ม
2. `ค้นเว็บ วิธีออมเงินสำหรับนักศึกษา` — ได้ปุ่มไปหน้าค้นหาใน MINI App ยังไม่ใช่ผลค้นเว็บที่ตอบครบในแชต
3. ในหน้าค้นหาให้ส่งคำค้นอีกครั้ง หากบริการค้นเว็บเปิดใช้และพร้อมจึงแสดงผลพร้อมแหล่งอ้างอิง หากไม่พร้อมควรแจ้งตามจริง

### S22 — ปฏิทินบิลประจำและการเตือนรายบิล

ฟีเจอร์นี้สาธิตโดยกด **เปิดแอป → ตั้งค่า → บิลประจำ** แล้วเลือกวัน เพิ่มบิล เลือกครั้งเดียว/ทุกเดือน เปิดการเตือนรายบิล และตรวจคำยืนยัน

**ตรวจ:** เลือกวันอย่างเดียวยังไม่สร้างบิล การสร้างตารางยังไม่จดรายจ่าย การแจ้งเตือนรายบิลเป็นล่วงหน้า 3 วันและวันครบกำหนด 09:00 ตามเวลาไทย เมื่อบริการส่งพร้อมและบิลยังไม่จ่าย

การพิมพ์ `เพิ่มบิล ...` ในแชตสร้างแผนบิล ไม่ได้เปิดตารางบิลรายเดือนหรือการเตือนรายบิลอัตโนมัติ ใช้ S22 เพื่อสาธิตส่วนนี้ให้ครบ

## สถานการณ์ป้องกันความผิดพลาด สำหรับช่วงถาม–ตอบ

ใช้บัญชีทดสอบและทดสอบแยกแต่ละแถว ไม่ต่อทุกแถวเป็นบทสนทนาเดียวโดยไม่ตรวจสถานะ

| รหัส | สิ่งที่ทดลอง | ผลที่ต้องตรวจ |
|---|---|---|
| E01 | จด `ข้าว 50` แล้วส่ง `ใช่ 40` โดยยังไม่เปิดคำขอแก้ | ไม่เพิ่มรายจ่ายชื่อ “ใช่” และไม่เดารายการที่จะแก้ |
| E02 | `แก้รายการล่าสุด` → `ใช่ 40` → `ยืนยัน` | แก้รายการเดิมเป็น 40 ได้ |
| E03 | `แก้ยอดล่าสุด 60` → `ใช่ 40` → กดการ์ดยืนยัน 60 เดิม | การ์ดเก่าต้องไม่ใช้ยอด 60; ยืนยันการ์ดใหม่จึงแก้ 40 |
| E04 | `แก้ยอดล่าสุด 60` → `แก้ยอดล่าสุด 40` → กดการ์ดยืนยันเดิม | คำสั่งใหม่ปิดการ์ดเก่า |
| E05 | อยู่ในคำขอแก้แล้วตอบ `-40`, `+40`, `๐`, `40.001`, `40 หรือ 50` ทีละเคส | ถามยอดใหม่ ไม่สร้างรายจ่ายอีกแถวจากข้อความเหล่านี้ |
| E06 | ขณะรอแก้ยอด พิมพ์ `ขอวิธีใช้` แล้ว `ใช่ 40` | เปิดคู่มือและยุติการตอบต่อคำขอเก่า ไม่แก้โดยเดา |
| E07 | `แก้ยอดล่าสุด 40` → `ยกเลิก` → กดการ์ดยืนยันเดิม | ไม่แก้ ไม่เพิ่มรายการ |
| E08 | สร้างร่างแก้ แล้วแก้ข้อมูลจาก MINI App ก่อนกลับมายืนยันร่าง | แจ้งข้อมูลเปลี่ยน ให้ตรวจใหม่ ไม่ทับข้อมูลล่าสุด |
| E09 | `จดหลายรายการพร้อมกันได้หรือไม่` | แสดงวิธีจด ไม่จดตัวอย่างที่อยู่ในคำตอบ |
| E10 | `รับเงิน 1000` และ `ข้าว 50` ในข้อความเดียว | ถามให้แยกประเภท ไม่รวมทั้งหมดเป็นรายจ่าย |
| E11 | `ข้าว 45 ไม่สิ 50` | ถามให้ระบุยอด/เจตนา ไม่เลือกยอดให้เอง |
| E12 | `กาแฟยังไม่ได้ซื้อ 50 แค่ดูราคา` | ไม่จดรายจ่ายที่ยังไม่เกิด |
| E13 | `เพื่อนโอนคืน` | ถามประเภทและยอดเพิ่มเติม ไม่เดาว่าเป็นรายรับ |
| E14 | `แก้วน้ำ 50 บาท` | ยังจดรายจ่ายทั่วไปได้ ไม่เข้าใจคำว่า “แก้ว” เป็นคำสั่ง “แก้” |
| E15 | กด **จดทั้งหมด** หรือ **ยืนยัน** บนการ์ดเดิมซ้ำ | ไม่ทำรายการซ้ำ; อย่าทดสอบด้วยการส่งข้อความรายจ่ายใหม่ซ้ำ |
| E16 | ค้นรายการที่ไม่มี เช่น `ค้นรายจ่าย รายการที่ไม่มี` | แจ้งไม่พบ ไม่สร้างประวัติปลอม |
| E17 | `ผ่อน โทรศัพท์ ยอดรวม 6000 บาท 0 งวด เริ่ม 2026-11-20` | แจ้งจำนวนงวดผิด ไม่สร้างบิล |
| E18 | `ผ่อน โทรศัพท์ ดาวน์ 1000 ดอกเบี้ย 5%` | ขอข้อมูลในรูปแบบยอดภาระจริง ไม่เดาดอกเบี้ยหรือสร้างรายจ่าย |
