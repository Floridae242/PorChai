| กรณีจากการทดสอบ | การแก้และหลักฐาน |

| คำสั่งแก้ยอด/ปรับยอด/เพิ่มบิลติดลบ | ป้องกันการดึงเฉพาะเลขบวกในตัวอ่านยอดร่วม; ทดสอบว่าไม่มีปุ่มยืนยันยอดผิดและไม่เปลี่ยนรายการ |
| ยังไม่จ่าย 3 หน้า 1 กลายเป็นหลายรายจ่าย | จับคำสั่งย้อนจ่ายบิลที่ระบุเป้าหมาย และต้องยืนยันก่อนเปลี่ยนข้อมูล |
| รายการหลายบรรทัดติดบริบทดูรายการ/ดูแผน/แก้รายการ | แยกรายจ่ายชุดใหม่ที่ชื่อและยอดชัดออกจากบริบทเก่า; แสดงร่างก่อนกดจดทั้งหมด |
| เพิ่มบิลวันที่ 2026-02-30 ถามยอดแทน | ตรวจวันในปฏิทินก่อนดำเนินการ แจ้งให้ตรวจวัน เดือน ปี |
| คำตอบไม่ตรงบุคลิก/สับสนว่าจดหรือยัง | กติกาน้องพอใช้ร่วมทุกงาน AI, prompt รายจ่ายร่วม, onboarding/คำตอบหลัก/คำอธิบาย MINI App และ error เชื่อมต่อ; แยกร่างกับรายการสำเร็จ |
| ชื่อปุ่มการ์ดบันทึกแคบ | เปลี่ยน footer เป็นแนวตั้ง มี contract test; ยังไม่ยืนยัน rendering หรือ contrast บน LINE จริง |

AI ใช้ผลจำลองใน regression tests ไม่ได้เรียก provider จริง ไม่ใช่หลักฐานว่าโมเดลทุกคำตอบรักษาบุคลิกได้เสมอ ต้องประเมินกับ provider เพิ่มเติมหลังตั้งค่าระบบ

ยังไม่ได้ทดสอบแต้ม sync บน production, OCR จริง, การแลกรางวัลจริง, แจ้งเตือนตามเวลา หรือ contrast ทุก LINE client ในรอบแก้ไขนี้ ไม่มีการเปลี่ยน environment หรือเขียนข้อมูล production
